# unslop-ko

[![license](https://img.shields.io/github/license/ProblmZro/unslop-ko)](LICENSE)

AI가 쓴 한국어 글에서 AI 티를 지우는 Claude Code 플러그인입니다. 숫자와 이름과 뜻은 그대로 두고, AI 글에 따라붙는 기호와 문장 틀만 고칩니다.

전:

```text
1차가 기능을 붙이는 단계였다면, 2차는 품질을 재는 단계였습니다.

- **재는 도구를 먼저 만들었습니다.** 문장마다 출처 원문과 대조합니다 — 1차에서 빠져 있던 가장 큰 구멍
- 검색·검토·운영 화면: 오탐 30건 중 12건 → 4건으로 감소
```

후:

```text
1차는 기능을 붙이는 단계였고, 2차는 품질을 재는 단계였습니다.

- 재는 도구를 먼저 만들었습니다. 문장마다 출처 원문과 대조합니다. 1차에서 빠져 있던 가장 큰 구멍입니다
- 검색, 검토, 운영 화면의 오탐이 30건 중 12건에서 4건으로 감소
```

1,045자짜리 프로젝트 정리 문서에 한 번 써 봤습니다. 진단 에이전트가 고칠 곳 25개를 찾았고 그중 23개를 고쳤습니다. 숫자는 모두 원문과 같았고 글자는 5% 바뀌었습니다. 남긴 2개는 제목에 든 가운뎃점입니다. 고유한 이름일 수 있어서 고치지 않고 되물었습니다.

AI 탐지기를 통과시키는 도구는 아닙니다. 사람이 읽기 편하게 고칠 뿐이고, 탐지기에 넣어 보지도 않았습니다.

## 이런 글에 씁니다

AI로 만든 보고서, 회의 정리, 안내문, 결산 문서처럼 업무에서 주고받는 글에 맞습니다. 이런 글 14개에서 되풀이되는 표현을 세어 고칠 표현의 목록을 만들었기 때문입니다.

홍보 문구나 소개문에는 약합니다. 상투어와 번역투가 많은 서비스 소개문 한 편에 써 봤습니다. 그 글에서 찾은 AI 티는 아홉 종류였는데, 이 플러그인은 번역투 두 종류만 없앴습니다. 그런 글에는 [humanizer-ko](https://github.com/IsaacEryn/humanizer-ko), [humanizer-kr](https://github.com/hjongc/humanizer-kr), [im-not-ai](https://github.com/epoko77-ai/im-not-ai)를 권합니다.

## 설치

Claude Code에서 아래 두 줄을 차례로 입력합니다. 2.1.331 버전에서 확인했습니다.

```text
/plugin marketplace add ProblmZro/unslop-ko
/plugin install unslop-ko@unslop-ko
```

Claude 데스크톱 앱의 Cowork에서도 동작을 확인했습니다. Cowork에 설치하는 방법은 앱의 플러그인 안내를 따르면 됩니다.

## 사용법

글을 붙여 넣고 이렇게 말하면 됩니다.

```text
이 글 AI 티 지워줘
```

"윤문해줘", "슬롭 지워줘", "자연스럽게 고쳐줘"라고 해도 됩니다. 결과는 다섯 가지로 나옵니다.

1. 고친 글
2. 바꾼 것과 그 개수
3. 그대로 둔 것과 이유
4. 되물을 것
5. 점검 결과

어디가 AI 티인지만 알고 싶을 때는 "고치지 말고 짚어만 줘"라고 합니다. 고칠 곳을 적은 목록만 돌려줍니다.

## 고치는 표현 아홉 가지

| 표현 | 전 | 후 |
| --- | --- | --- |
| 가운뎃점 나열 | 검색·검토·운영 화면 | 검색, 검토, 운영 화면 |
| 줄표로 덧붙이기 | 원문과 대조합니다 — 가장 큰 구멍 | 원문과 대조합니다. 가장 큰 구멍입니다 |
| 화살표 | 10건 → 3건 | 10건에서 3건으로 |
| 괄호 보충 | 꺼 뒀던 기능(이유 문장 생성 포함) | 꺼 뒀던 기능. 이유 문장 생성도 여기에 든다 |
| "라벨: 내용" 줄 | 비용: 지난달 약 12만 원 | 지난달 비용은 약 12만 원이다 |
| 굵은 머리 문장 | `**재순위를 켰습니다.**` 응답이… | 재순위를 켰습니다. 응답이… |
| "A였다면 B", "X가 아니라 Y" | 1차가 A였다면 2차는 B. 핵심은 X가 아니라 Y다 | 1차는 A였고 2차는 B. 핵심은 Y다 |
| 따옴표와 낫표 강조 | "그대로 옮김"과 「정리함」 | 그대로 옮김과 정리함 |
| 번역투 | 설계되어졌습니다, ~를 통해 | 설계되었습니다, ~로 |

한 번 나왔다고 다 고치지는 않습니다. 괄호 보충, 따옴표 강조, "X가 아니라 Y"는 글 전체에서 두 번째부터, 번역투는 한 문단에 세 번 이상일 때 고칩니다. 표현마다 정한 기준은 [SKILL.md](skills/unslop-ko/SKILL.md)에 있습니다.

## 고치지 않는 것

문서 양식은 건드리지 않습니다. 같은 종류의 문서를 사람이 써도 나오는 모양이면 양식으로 봅니다.

- 일시, 참석자, 작성자 같은 문서 머리 정보
- 표 머리글과 목록의 줄머리 기호
- [목적], [진행상황] 같은 보고 머리글
- 명사로 끝나는 개조식 줄
- 날짜, 버전, 경로 표기
- 버튼 이름, 코드, 인용문

숫자, 이름, "예정"이나 "완료" 같은 진행 상태도 바꾸지 않습니다. 비유는 지우면 내용이 빠지므로 그대로 둡니다. 원문에 없는 내용은 지어내지 않고 질문으로 돌려줍니다.

## 동작 방식

글을 쓴 모델은 자기 글의 흠을 잘 못 봅니다. 그래서 고칠 곳을 정하는 일, 고치는 일, 점검하는 일을 서로 다른 에이전트에게 맡겼습니다. 아래에서 주 에이전트는 사용자와 대화하는 Claude를 말합니다.

1. 스크립트가 글자 수와 기호를 셉니다.
2. 500자 이하면 주 에이전트가 직접 고치고 6번으로 갑니다.
3. 진단 에이전트가 양식으로 둘 곳, 바꾸면 안 되는 것, 고칠 곳을 적습니다. 글은 고치지 않습니다.
4. 고칠 곳이 없으면 여기서 끝냅니다.
5. 윤문 에이전트가 진단서에 적힌 곳만 고칩니다.
6. 점검 에이전트가 원문과 고친 글만 받아 대조합니다. 진단서는 받지 않습니다.
7. 스크립트가 원문과 고친 글의 숫자를 대조합니다. 어긋난 줄은 주 에이전트가 원문으로 되돌립니다.

들어 있는 파일은 다음과 같습니다.

| 파일 | 하는 일 |
| --- | --- |
| `skills/unslop-ko/SKILL.md` | 전체 절차와 고칠 표현의 기준 |
| `agents/unslop-diagnostician.md` | 진단 |
| `agents/unslop-rewriter.md` | 윤문 |
| `agents/unslop-checker.md` | 점검 |
| `scripts/unslop_check.py` | 기호 세기와 숫자 대조 |

## 스크립트만 쓰기

글을 고치지 않고 세기와 대조만 할 수 있습니다. 파이썬 3만 있으면 되고, 다른 라이브러리나 네트워크는 쓰지 않습니다.

```text
python3 scripts/unslop_check.py count 원문.txt
python3 scripts/unslop_check.py compare 원문.txt 고친글.txt
```

`count`는 글자 수와 표현별 개수를 냅니다. `compare`는 원문에만 있는 숫자와 고친 글에만 있는 숫자, 바뀐 비율을 냅니다. 숫자가 어긋나면 종료 코드 1을, 바뀐 비율이 50%를 넘으면 2를 냅니다.

## 근거

AI로 만든 업무 문서 14개, 35만 자에서 표현을 세었습니다. 주제가 달라도 똑같이 따라붙는 것을 골랐습니다.

| 표현 | 천 자당 | 나온 문서 |
| --- | --- | --- |
| 가운뎃점 | 14.4번 | 14개 모두 |
| 괄호 보충 | 3.4번 | 13개 |
| 화살표 | 1.3번 | 12개 |
| 줄표 | 1.2번 | 9개 |
| "라벨: 내용" 줄 | 1.0줄 | 12개 |
| "X가 아니라 Y" | 0.3번 | 10개 |

흔히 AI 티로 꼽는 표현은 오히려 드물었습니다. 같은 35만 자에서 번역투(~를 통해, ~에 있어, 이중 피동)는 모두 합쳐 4번, "다양한", "또한", "첫째"는 모두 합쳐 6번 나왔습니다.

고치는 표현 아홉 가지 가운데 표에 없는 것이 셋 있습니다. 굵은 머리 문장은 14개 중 8개 문서에서 249번 나왔습니다. 따옴표 강조는 문서를 읽다가 눈에 띄어 넣었고, 번역투는 드물었지만 다른 스킬이 공통으로 다루는 것이라 넣었습니다. 이 둘은 센 근거가 약합니다.

## 한계

- 문서 14개는 모두 한 사람이 AI로 만든 것입니다. 다른 사람이나 다른 종류의 글에서는 개수가 다를 수 있습니다.
- 500자가 넘는 글은 에이전트를 세 번 부릅니다. 1,045자 글에 4분쯤 걸렸습니다.
- 사실은 확인하지 않습니다. 원문의 수치가 의심스러우면 고치지 않고 되묻습니다.
- 숫자를 대조하려고 원문과 고친 글을 작업 폴더에 파일로 저장합니다.

세 프로젝트 모두 MIT 라이선스이고, 문장을 옮겨 오지는 않았습니다.

## 버전 이력

- 0.1.1: 500자를 넘는 글은 기호 개수와 상관없이 에이전트 셋을 거칩니다. 0.1.0은 기호가 5개 이하면 긴 글도 주 에이전트가 직접 고쳤습니다. 스크립트가 굵은 머리 문장, 괄호, "라벨: 내용" 줄, "아니라", 따옴표 개수도 셉니다.
- 0.1.0: 첫 공개.
